# 동작 검사

이 파일은 원본과 별개로 작성한 시험용 연결 스킬이다. 원본을 실제로 읽고 허용된 절차를 적용한다. 원본 전체 런타임 실행과 구분한다.

## 먼저 읽을 파일

1. 형제 폴더 `../sk-ai-exam-operator/references/skill-routing.md`의 공통 실행 계약.
2. 형제 운영 스킬의 `upstream/superpowers/skills/test-driven-development/SKILL.original.md` 원본 전체. 아래 지원 문서의 경로는 해당 프로젝트의 `upstream/superpowers/` 기준이다.

최초 적용에는 위 원본을 읽는다. 동일 버전 원본과 공통 계약이 현재 문맥에 남아 있는 재진입에는 재사용하고 필요한 절만 확인한다. 문맥을 잃거나 파일이 바뀌면 다시 읽고, 실제 최초 읽기와 재사용을 구분한다.

원본이 없거나 잠금 해시가 맞지 않으면 원본 적용 성공으로 표시하지 않는다. 문제를 짧게 알리고 운영 스킬의 기본 도구로 가능한 작업을 이어간다. 준비되지 않은 명령·별도 런타임을 설치하지 않는다.

## 현재 단계의 적용

- 원본의 RED→GREEN→REFACTOR를 업무 동작에 적용한다. 정상 사례와 현재 위험한 예외의 입력·기대 결과를 먼저 정하고 실패를 관찰한 뒤 최소 구현하고 재실행한다.
- 기존 구현이 이미 있으면 먼저 현재 동작을 관찰한다. RED를 관찰하지 않았다면 그 사실을 적으며 실패 이력을 꾸미거나 RED를 만들기 위해 동작 중인 코드를 삭제하지 않는다.
- 단순 문구·기록 갱신 등 저영향 변경에 형식적인 테스트를 만들지 않는다. 추가 의존성 설치 없이 기존 검사 도구와 기본 실행 방법을 쓴다.
- **구현 역할(세션 1)**: 업무 규칙마다 작은 검사를 함께 둔다(규칙 하나 = 검사 하나).
- **검토 역할(세션 2)**: 결과 파일을 읽어 필수 F·중요 E의 제약을 해법 코드와 별도로 다시 계산하는 검사를 만든다. 해법 모듈의 같은 함수로 자기 결과를 확인하지 않는다. 검사 파일은 `review/`에 두고 과제 코드는 고치지 않는다. 일부러 망가뜨린 결과(누락·한도 초과·잘못된 단위 등)로 각 검사가 실패를 잡는지 먼저 확인한다. 검사 대상이 0건이거나 전부 건너뛰면 통과가 아니라 미검증이다.
- `05_verification.md`에 실제 명령·입력·기대·실제·판정·연결한 F/E ID를 적는다. 수동 UI는 참가자의 실제 관찰과 AI가 실행한 검사를 구분한다. 실패하면 `sk-exam-debug`로 이어간다.

## 결과 연결

현재 사용한 스킬·원본 경로·원본 적용 범위·중요 생략을 `05_verification.md`의 스킬 적용 기록에 짧게 남긴다. 파일을 읽은 사실과 검사 실행·기능 완료는 별개다. 끝나면 운영 스킬로 돌아가 남은 시간과 실제 상태에 맞는 다음 한 작업을 이어간다.
