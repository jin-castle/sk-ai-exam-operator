# 문제 구조화와 시각화

이 파일은 원본과 별개로 작성한 시험용 연결 스킬이다. 원본을 실제로 읽고 허용된 절차를 적용한다. 원본 전체 런타임 실행과 구분한다.

과제 대부분은 겉모습만 보면 짧은 바이브 코딩으로 돌아가는 결과가 나온다. 점수가 갈리는 곳은 **구체적으로 들어갔을 때 어디서 틀리는지**를 담당자 인터뷰로 찾아내고 그걸 구현에 반영하는 부분이다. 이 스킬의 목적은 참가자가 문제를 빨리 이해하게 돕고, 그 “깨지는 지점”을 인터뷰 질문으로 바꾸는 것이다. 정답을 추측해 사실처럼 채우는 것이 아니다.

**참가자가 먼저, AI는 빈칸만.** 평가는 대화·기록으로 참가자의 의도와 이해를 본다. AI가 지도와 질문을 먼저 다 만들고 참가자가 그대로 옮기면, 기록에 남는 문제 이해의 근거가 AI 출력뿐이다. 그래서 AI는 자료의 사실만 먼저 정리하고, 문제·원인·위험한 가정·질문은 참가자가 먼저 자기 말로 쓴다. AI는 그 목록에서 빠진 범주만 짚고, 고르고 고쳐 쓰는 것은 참가자가 한다. 모든 가정·질문에 출처(참가자 / AI 제안→참가자 수정 / AI 제안 그대로)를 남긴다.

## 먼저 읽을 파일

1. 형제 폴더 `../sk-ai-exam-operator/references/skill-routing.md`의 공통 실행 계약.
2. 형제 운영 스킬의 `upstream/superpowers/skills/brainstorming/SKILL.original.md` 원본 전체. 지원 문서 경로는 `upstream/superpowers/` 기준이다.
3. 빈 양식 `../sk-ai-exam-operator/assets/templates/00_problem_map.md`.

최초 적용에는 위 원본을 읽는다. 동일 버전 원본과 공통 계약이 현재 문맥에 남아 있는 재진입에는 재사용하고 필요한 절만 확인한다. 원본이 없거나 잠금 해시가 맞지 않으면 원본 적용 성공으로 표시하지 않고 기본 도구로 이어간다.

원본에서 적용하는 것: 묻기 전에 자료부터 보기, 이해한 내용을 되돌려 말하기(play back), 작업 크기 가늠. **적용하지 않는 것**: Visual Companion의 로컬 서버·브라우저(`scripts/`), 설계 승인 전 구현 금지 gate, 설계 문서 커밋. 시험에서는 브라우저를 열지 않고, 첫 흐름 구현을 늦추지 않는다.

## 누가, 언제

- **세 세션**: 세션 3이 시작 직후 맡는다(세션 1은 그동안 자료·실행 환경을 확인). 결과는 `exam-notes/00_problem_map.md`이며 세션 3이 쓴다. 세션 1은 읽어서 인터뷰와 첫 흐름 범위에 쓴다.
- **한 세션**: 세션 1이 담당자 인터뷰 전에 15분 안에 만든다.
- 담당자 답변이 들어올 때마다 지도의 가정 상태(확인 / 반박 / 미확인)만 갱신한다. 지도를 다시 그리느라 구현을 멈추지 않는다.

## 만드는 순서 (15분 안팎)

### 1단계 · AI: 자료의 사실만 정리 (~5분)

- 과제 원문 위치, 제공 데이터의 파일·열·행 수·표본 몇 줄, 기존 코드·실행 방법을 확인한다. 좌표·수치 데이터면 아래 `scatter`로 분포를 한 번 그리고 요약 숫자(결측·범위 밖·그룹별 개수)를 적는다.
- `00_problem_map.md`의 ‘자료 사실’ 칸에 **관찰한 사실만** 쓴다. 문제 정의·원인·가정·질문은 이 단계에서 쓰지 않는다.

### 2단계 · 참가자: 내 말로 먼저 (~5분)

참가자에게 아래 네 가지를 자기 말로 짧게 써 달라고 요청한다. **AI의 예시 답·모범 지도를 먼저 보여 주지 않는다.**

1. 풀어야 할 문제 한 문장(누가 / 무엇을 / 왜 지금 못 하나)
2. 이 문제가 생긴 근본 원인이라고 생각하는 것
3. 30분 만에 만든다면 무엇을 만들지, 그 해법에서 가장 위험한 가정
4. 담당자에게 묻고 싶은 질문 3개

받은 내용은 고치지 않고 ‘0. 참가자가 먼저 쓴 것’에 원문으로 붙인다. 참가자가 기다리는 동안 AI는 그림 그리기·자료 확인처럼 답에 의존하지 않는 일만 한다. 참가자가 이번에 쓰지 않겠다고 하면 그 사실을 적고 3단계로 가되, 이후 AI가 채운 모든 줄은 `AI 제안`으로 표시한다.

### 3단계 · AI: 빈칸만 짚기 (~3분)

- 참가자의 목록을 아래 점검 목록의 범주에 대응시키고 **비어 있는 범주만** 알려 준다. 각 빈 범주에는 가능하면 1단계의 데이터 관찰을 붙인 질문 후보를 하나 제시한다(출처: AI 제안).
- 참가자의 질문을 대신 고쳐 쓰지 않는다. 포괄 질문(“다 알려 주세요”)이나 여러 주제가 섞인 질문이 있으면 그 사실만 짚고, 나누는 것은 참가자가 한다.
- 참가자의 원인·가정이 자료 사실과 어긋나면 어느 사실과 어긋나는지만 알려 준다.

### 4단계 · 참가자: 고르고 고쳐 쓰기 (~2분)

- AI 후보마다 채택 / 수정 / 제외와 이유 한 줄을 받는다. 채택한 후보는 참가자가 자기 말로 바꾸고 데이터 관찰을 붙이도록 권한다(“상태가 ‘중지’인 312건도 대상에서 빼나요?”가 “빼야 할 건이 있나요?”보다 낫다).
- 질문 표의 출처 칸에 `참가자 / AI 제안→참가자 수정 / AI 제안 그대로`를 적는다. `AI 제안 그대로`가 많으면 참가자에게 알린다.

### 5단계 · 지도와 그림 완성

참가자 입력과 채택된 보완으로 나머지 칸을 채운다: 지금 → 바라는 상태와 근본 원인(근거 상태 표시), 시스템 경계(입력 → 처리 → 출력 → 사용자별 행동), 단순 해법의 숨은 가정 → 깨지는 지점, 영향 큰 순의 인터뷰 질문(답에 따라 바뀌는 코드·결과), 접근 순서(첫 end-to-end 범위 / 답을 받은 뒤 붙일 것 / 하지 않을 것). 새 내용을 AI가 덧붙였으면 출처를 `AI 제안`으로 둔다. 그다음 아래 스크립트로 그림을 그린다.

### 깨지는 지점 점검 목록

| 범주 | 단순 해법이 흔히 깔고 있는 가정 | 질문 예(업무 언어로) |
|---|---|---|
| 대상 범위 | 데이터의 모든 행이 대상이다 | “이 결과에서 빼야 하는 사람·건이 있나요?” |
| 한도·제약 | 과제에 적힌 제약만 있다 | “처리 시간·횟수 같은 한도가 있나요?”, “쓸 수 있는 자원(인력·장비·예산)은 몇까지인가요?” |
| 시간·순서 | 시각이 하나다, 순서는 상관없다 | “성격이 다른 그룹을 한 번에 처리해도 되나요?”, “마감·시작 시각 제한이 있나요?” |
| 우선순위 충돌 | 효율 하나만 최적화하면 된다 | “비용과 편의가 부딪히면 무엇을 먼저 지켜야 하나요?” |
| 예외 데이터 | 데이터가 깨끗하다 | “같은 사람이 여러 줄이면 어느 것을 믿나요?”, “단위·형식이 섞여 있으면?” |
| 변경 운영 | 한 번 계산하면 끝이다 | “조건을 바꾸면 누구에게 무엇을 알려야 하나요?”, “기존 결과를 얼마나 유지해야 하나요?” |
| 사용자·권한 | 모든 사용자가 같은 화면을 본다 | “일반 사용자에게 보이면 안 되는 정보가 있나요?” |
| 결과의 쓰임 | 숫자만 내면 된다 | “이 결과를 누가 보고 무엇을 결정하나요? 어떤 형식이어야 하나요?” |

이 표는 3단계에서 **빈 범주를 찾는 데만** 쓴다. 표의 질문 예를 그대로 참가자에게 먼저 보여 주거나 목록째 담당자에게 옮기지 않는다. “필요한 거 다 알려 주세요” 같은 포괄 질문, 여러 주제를 한 번에 묻는 질문은 만들지 않는다. 담당자에게는 참가자가 직접, 한 번에 한 주제씩 묻는다.

## 시각화 — Python 스크립트

이미지 생성 도구에 의존하지 않는다. 이 스킬 폴더의 `scripts/frame_viz.py`(표준 라이브러리만 사용)로 그린다. `SKILL_DIR`은 이 스킬의 실제 설치 폴더로 바꾼다. 새 패키지를 설치하지 않고, 브라우저를 열지 않는다.

1. **문제 지도 그림**: 위 순서로 정리한 내용을 JSON으로 옮겨 그린다.

   ```text
   python -X utf8 -B "SKILL_DIR/scripts/frame_viz.py" template --out exam-notes/problem_map.json
   (problem, causes[{text,status}], effects, flow{inputs,process,outputs,users[{name,action}]},
    assumptions[{assumption,breaks,question,status,by}] 를 채운다. by는 참가자 / AI 제안→참가자 수정 / AI 제안)
   python -X utf8 -B "SKILL_DIR/scripts/frame_viz.py" map exam-notes/problem_map.json --out exam-notes/problem_map.svg --png
   ```

   ① 원인(근거 상태 색) → 문제 → 증상, ② 입력 → 처리 → 출력 → 사용자, ③ 숨은 가정 → 깨지는 지점 → 인터뷰 질문, 세 묶음이 한 장에 나온다. status는 `확인 / 반박 / 미확인 / 가설`이고, 가정 칸의 꼬리표에 출처(by)가 함께 표시된다.

2. **데이터 분포 그림**: 좌표·두 수치 열이 있는 데이터면 먼저 한 번 그려 본다. 문제를 눈으로 이해하는 데 가장 빠르고, 요약 JSON이 데이터 품질 단서를 함께 준다.

   ```text
   python -X utf8 -B "SKILL_DIR/scripts/frame_viz.py" scatter data/주요.csv --x X열 --y Y열 --group 구분열
       [--overlay data/보조.csv --overlay-x 열 --overlay-y 열 --overlay-label 이름] [--mark 0,0:기준점]
       --title 제목 --out exam-notes/data_scatter.svg --png [--encoding cp949]
   ```

   요약의 `skipped_non_numeric`(결측·숫자 아님), `outside_view`(가운데 99 % 보기 범위 밖 개수 — 정상 분포에서도 일부 나온다. 값이 수십·수천 배 벗어난 행만 단위 오류·이상값 후보), 그룹별 개수를 깨지는 지점과 인터뷰 질문에 바로 연결한다. 보기 범위는 기본으로 가운데 99 %이며 `--clip-pct 100`이면 전부 보인다.

- `--png`는 matplotlib과 한글 글꼴이 **이미 있을 때만** PNG를 함께 만든다. 없으면 SVG만 만들고 요약에 이유를 적는다. 화면에서 SVG를 볼 수 없고 PNG도 없으면 지도 MD의 표와 텍스트 도식으로 진행한다.
- 음수 좌표 기준점은 `--mark=-1.5,2:이름`처럼 `=`로 붙여 쓴다. 한글 CSV가 깨지면 `--encoding cp949`.
- 종료 코드: 0 정상, 1 입력 오류(없는 열 이름 등 — 오류 메시지에 실제 열 목록이 나온다), 2 그릴 것이 없음. 2를 성공으로 읽지 않는다.
- `00_problem_map.md`에는 그림 파일 경로와, Mermaid가 보이는 화면을 위한 Mermaid 블록·텍스트 도식을 함께 둔다.
- 그림은 이해를 돕는 자료이며 구현·검증의 근거가 아니다. 그림 속 가정도 표의 근거 상태를 따른다. 실제 데이터로 그린 그림은 작업 폴더 밖으로 보내지 않는다.

## 결과 연결

- 인터뷰 질문은 `sk-exam-interview`의 출발점으로 쓴다. 받은 답은 세 세션이면 세션 1이 `10_work_log.md`에 원문으로, 한 세션이면 `01_domain.md`에 남기고, 지도의 해당 가정 상태를 갱신한다.
- 사용한 원본·적용 범위·생략(Visual Companion 서버 미실행 등)을 `05_verification.md`의 스킬 적용 기록에 짧게 남긴다. 끝나면 운영 스킬로 돌아가 다음 한 작업을 이어간다.
