# 완료 근거 확인

이 파일은 원본과 별개로 작성한 시험용 연결 스킬이다. 원본을 실제로 읽고 허용된 절차를 적용한다. 원본 전체 런타임 실행과 구분한다.

## 먼저 읽을 파일

1. 형제 폴더 `../sk-ai-exam-operator/references/skill-routing.md`의 공통 실행 계약.
2. 형제 운영 스킬의 `upstream/superpowers/skills/verification-before-completion/SKILL.original.md` 원본 전체. 아래 지원 문서의 경로는 해당 프로젝트의 `upstream/superpowers/` 기준이다.

최초 적용에는 위 원본을 읽는다. 동일 버전 원본과 공통 계약이 현재 문맥에 남아 있는 재진입에는 재사용하고 필요한 절만 확인한다. 문맥을 잃거나 파일이 바뀌면 다시 읽고, 실제 최초 읽기와 재사용을 구분한다.

원본이 없거나 잠금 해시가 맞지 않으면 원본 적용 성공으로 표시하지 않는다. 문제를 짧게 알리고 운영 스킬의 기본 도구로 가능한 작업을 이어간다. 준비되지 않은 명령·별도 런타임을 설치하지 않는다.

## 현재 단계의 적용

- 원본의 완료 주장→입증할 명령→전체 실행→출력·종료 상태 확인→근거에 맞는 표현을 적용한다. 변경 이전 검사로 최신 변경을 통과 처리하지 않는다.
- 반복 검사에는 형제 운영 스킬의 [실행 근거 가드](../sk-ai-exam-operator/references/evidence-guard.md)를 선택적으로 쓴다. 검사 범위에 관련 소스·설정·입력과 실제 테스트를 포함하고, 등록한 필수 항목과 명령을 연결한다. 코드·요구사항 변경, 실행 중 변경, 최신 실패·시간 초과, 누락·변경된 로그는 성공 근거로 재사용하지 않는다.
- 가드의 `recorded_checks_current`는 등록한 항목과 지정한 파일 범위의 실행 기록만 뜻한다. 미등록 요구사항·잘못된 기대값·검사가 없는 테스트·수동 UI·업무 정답은 별도 확인하고, 단순 종료 코드 0으로 이들을 통과 처리하지 않는다.
- 필수 기능과 중요한 예외별 구현·실행 근거·미검증을 `05_verification.md`에 연결한다. 빌드 성공·업무 규칙 검사·저장 복구·참가자 수동 UI 관찰을 구분한다.
- 입력 검증·권한·민감 정보 노출·저장 복구 중 과제에 해당하는 위험을 실제 검사 근거 또는 미검증 이유와 연결한다. 없는 기능은 추가하지 않는다.
- 운영 지침의 참가자 먼저 설명 확인이 아직 없고 시간이 충분하면 AI 모범 설명 전에 짧은 질문을 한다. 실제 답변 없이 참가자 이해를 확인됐다고 쓰지 않고 독립적인 검증은 계속한다.
- 실제 함수·상태·데이터 흐름·실패 조건을 설명과 대조하고 구현되지 않은 기능은 한계로 밝힌다. 검증이 불가능하면 불가 사유와 확인 가능한 범위를 보고한다.
- **문서화 역할(세션 3)**: `06_handoff.md`와 과제가 요구한 제출 문서의 주장마다 실제 검사 T 또는 파일·함수를 연결한다. 연결할 근거가 없는 주장은 미검증으로 바꾸거나 지운다. 문서에 적힌 실행 명령은 실제로 다시 실행해 확인한다. 문서를 쓰다 발견한 결함은 고치지 않고 참가자에게 알려 세션 1에 반영을 요청한다(한 세션 운영이면 제출을 막는 것만 최소 수정·재검사). 나머지는 감수한 한계로 남긴다. 다시 실행한 명령의 출력이 세션 1의 결과물을 덮어쓰면 안 된다.
- 이 단계는 자동 제출이나 후속 서술형 답안 작성을 포함하지 않는다. 과제 시간 만료·AI 금지 단계 보고가 먼저 오면 작업을 멈춘다.

## 결과 연결

현재 사용한 스킬·원본 경로·원본 적용 범위·중요 생략을 `05_verification.md`의 스킬 적용 기록에 짧게 남긴다. 세 세션 운영이면 세션 1은 `exam-notes/10_work_log.md`, 세션 2는 `exam-notes/20_review.md`에 같은 내용을 남기고 세션 3이 01~05로 옮긴다. 파일을 읽은 사실과 검사 실행·기능 완료는 별개다. 끝나면 운영 스킬로 돌아가 남은 시간과 실제 상태에 맞는 다음 한 작업을 이어간다.
