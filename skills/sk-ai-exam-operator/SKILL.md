# SK AI 시험 운영

한 번 활성화하면 현재 시험 대화의 후속 답변·시간 보고·구현 작업에도 아래 운영을 이어간다. 별도 데몬·알람·자동 브라우저·백그라운드 감시를 만들지 않는다. 과제 자체의 요구와 최신 응시 안내를 우선한다.

## 세 역할(세션)

과제 하나를 세 세션이 나눠 맡는다. 세션 1이 만들고, 세션 2가 세션 1의 결과를 검토하고, 세션 3이 1·2의 작업을 구조화해 문서로 만든다. 같은 작업 폴더를 공유하고 자기 파일만 쓴다. **시작할 때 이 세션의 역할을 확인한다.** 참가자가 역할을 말하지 않았으면 세션 1(구현)로 본다.

| 역할 | 하는 일 | 쓰는 파일 | 하지 않는 것 |
|---|---|---|---|
| **1 구현** | 인터뷰·설계 → 가장 단순한 end-to-end → 필수 기능, 검토 발견 반영 | 과제 코드·결과물, `10_work_log.md`, 시간 상태 | 검토·문서 파일 수정 |
| **2 검토** | 기대값 먼저 → 독립 검사기 → AI가 혼자 정한 것·요구 충족·품질 검토 → 조건 변경 재실행 | `20_review.md`, `exam-notes/review/` | 과제 코드 수정(발견만 넘김), 커밋 |
| **3 문서화** | 작업 로그·검토 기록을 Q/F/E/D/T와 `06_handoff.md`·제출 문서로 구조화, 근거 대조 | `00_problem_map.md`, `01~06`, 제출 문서 | 코드·판정 변경, 이유 대필, 커밋 |

세션끼리는 파일과 참가자를 통해서만 연락한다. 커밋은 세션 1만 한다. 세션을 하나만 열 수 있으면 한 세션이 세 역할을 시간 순서로 맡는다. 역할별 절차와 파일 소유권은 [세 역할](references/roles.md), 한 세션일 때의 시간 기준은 [시간 운영](references/operation.md)을 읽는다.

## 시작과 종료 경계

1. **가장 먼저 현재 단계를 확인한다.** 사용자가 후속 서술형·AI 금지 단계에 들어갔다고 하면 도구 호출, 파일 수정, 문항 분석·답안 작성·첨삭 없이 지원을 멈춘다고 한 문장만 알린다. 남은 시간·활성 상태가 있어도 이 경계가 우선한다. 정상 과제가 진행 중이라는 근거 없이 다시 시작하지 않는다.
2. 남은 시간이 0 이하라는 보고에는 개발·검사·기록 작업을 시작하지 않고 플랫폼 안내와 제출 상태를 참가자가 직접 확인하도록 짧게 알린다. 완료·중단 요청이면 운영을 종료한다.
3. 과제 중이면 목표·필수 결과·현재 파일·기존 실행 방법을 먼저 읽는다. 사용자가 이미 구현한 내용을 유지하고 필요한 작업을 이어간다. 정해진 연습용 도메인이나 아키텍처를 주입하지 않는다.
4. 참가자가 명시한 잔여 시간을 받는다. 없으면 현재 화면의 남은 시간을 한 번 요청하면서 독립적인 자료 확인을 계속한다. **180분은 계획 기준이지 현재 잔여 시간의 측정값이 아니다.** 플랫폼 타이머·호스트 시계·대기 시간을 임의로 환산하지 않는다.
5. 과제 작업 폴더 안에 `exam-notes/`를 준비한다. 지정 양식이 있으면 먼저 읽고 해당 양식을 재사용한다. 이미 동등한 기록이 있으면 위치를 매핑하고 중복 파일을 강제 생성하지 않는다. 다른 세션이 이미 `exam-notes/`를 만들었으면 다시 만들지 않고 그대로 쓴다.
6. 이 세션의 역할(1 구현 / 2 검토 / 3 문서화)을 확인하고 [세 역할](references/roles.md)의 해당 절을 따른다. 다른 역할의 파일은 읽기만 한다.

### 선택적 보조 스크립트

Python이 이미 사용 가능하고 로컬 실행이 허용된 경우에만 아래를 쓴다. `SKILL_DIR`는 지금 읽은 이 스킬의 실제 폴더로 바꾼다. 작업 폴더를 명시한다. 새 런타임을 설치하지 않는다.

```text
python -X utf8 -B "SKILL_DIR/scripts/exam_session.py" init --root "exam-notes"
python -X utf8 -B "SKILL_DIR/scripts/exam_session.py" checkpoint --root "exam-notes" --remaining 72
python -X utf8 -B "SKILL_DIR/scripts/exam_session.py" status --root "exam-notes"
```

`--remaining`은 **사용자가 실제로 보고한 경우에만** 전달한다. 없으면 생략한다. 스크립트는 시간대별 권고 구간과 마지막 보고를 기록할 뿐, 업무 진행도나 테스트 결과를 판단하지 않는다. 재호출·재개는 기존 상태를 보존하며 타이머를 초기화하지 않는다. `status`는 읽기 전용이다.

Python이 없거나 지정 문서를 재사용하면 기본 파일 도구로 같은 기록을 관리한다. [기록 계약](references/records.md)을 읽고 빈 양식이 필요할 때만 `assets/templates/`를 사용한다. 스크립트 사용은 이 스킬의 필수 조건이 아니다.

### 선택적 실행 근거 검사

실제 명령을 반복 실행하거나 코드·요구사항이 바뀐 뒤 완료 근거를 재확인할 때 [실행 근거 가드](references/evidence-guard.md)를 읽고 `scripts/evidence_guard.py`를 사용할 수 있다. 필수 항목의 기대 동작·출처와 검사 명령을 연결하고, 관련 소스·설정·입력의 실행 전후 및 현재 해시를 비교한다. 최신 실패·시간 초과·누락·오래된 근거가 있으면 재검증한다. 단순 명령 성공을 업무 정답·전체 과제 완료로 바꾸지 않는다.

이 도구는 선택적이다. 기존 타이머와 본문 MD를 바꾸지 않으며, 실제 과제의 단계·도구 허용 조건을 대신 판단하지 않는다. 번들 검사 통과, 기록된 명령의 최신성, 의미상 요구사항 충족, 참가자 수동 관찰은 각각 구분한다.

## 대화마다 적용할 운영 순서

1. **단계·시간 보고를 먼저 반영한다.** 새로운 실제 시간 보고가 없으면 마지막 값을 ‘마지막 보고’로 표현한다. 스크립트를 재실행한 시각이 새 타이머 확인은 아니다.
2. **새 근거를 분류한다.** 담당자 답변·과제 명시·데이터 관찰·참가자 가정·AI 제안·미확인을 구분하고 바뀐 행만 갱신한다. 이전 답변과 충돌하면 최신 근거와 영향받는 기능·검사를 확인한다.
3. **이 역할의 다음 한 작업을 정한다.** [세 역할](references/roles.md)과 필요하면 [시간 운영](references/operation.md)을 읽고, 다른 세션이 남긴 최신 기록(작업 로그·검토 발견)·실제 구현·검증 상태와 큰 오판을 기준으로 선택한다. 시각만 맞추려고 완료 처리하거나 필수 정책을 건너뛰지 않는다.
4. **짧게 안내하고 허용된 작업을 진행한다.** 목표·변경 범위·완료 조건이 명확한 읽기·구현·검사·기록은 재승인을 묻지 않고 실행한다. 업무상 판단 공백만 참가자에게 확인한다. 지침을 출력하고 매번 사용자에게 작업을 떠넘기는 안내 전용 모드로 머물지 않는다.
5. **실제 결과로 닫는다.** 실행·관찰한 범위만 검증으로 표시한다. 실패면 재현과 원인 확인 후 최소 수정으로 이어간다. 문서의 판단 이유는 참가자가 실제 밝힌 내용만 기록한다.

기능·대화 묶음 종료 때 또는 마지막 보고 기준 약 20분 분량의 작업이 진행됐을 때 다음 체크포인트에서 최신 잔여 시간을 요청한다. 실제 경과를 알 수 없으면 분 단위가 지났다고 단정하지 않는다. 타이머 보고가 없다고 모든 작업을 중단하지 않는다. 루프·sleep으로 시간을 기다리거나 이 스킬만으로 나중에 알림을 보낼 수 있다고 약속하지 않는다.

## 담당자 질문과 구현의 연결

- 처음에는 최근 실제 사례, 다음 의사결정, 가장 큰 오판을 묻는다.
- 파일에서 확인 가능한 사실은 먼저 조사한다. 사람에게는 조건·우선순위·누락·충돌·실패의 업무적 처리 정책을 묻는다.
- 후보 질문마다 ‘답이 바뀌면 어떤 코드·우선순위·기대 결과가 바뀌는가’를 확인한다. 현재 높은 영향의 질문 1~3개부터 제안한다. 이는 총 질문 수 제한이 아니다.
- 답변을 조건→처리→예외→성공 기준으로 재진술한다. 중요한 의미가 모호하면 확인하고, 독립적인 구현은 계속한다.
- 생성된 질문 초안은 참가자가 사실·맥락·표현을 직접 검토한 뒤 사용한다. 참가자가 직접 담당자와 대화한다. 질문 초안·답변 정리는 돕되 자동 연락·클릭·입력으로 확장하지 않는다. 담당자 답변을 받지 않았으면 확정 정책으로 만들지 않는다.
- 목표·핵심 규칙·성공 기준이 확보되면 작은 사용자 흐름을 구현한다. 직접 사용과 검사에서 새 업무 경계가 드러나면 그 부분만 다시 질문한다.

## 함께 설치한 단계별 스킬을 호출하는 방법

v3.0.2 팩에는 이 운영 스킬과 단계별 연결 스킬 10개, 고정된 Superpowers·gstack·Ouroboros 원본·지원 문서·LICENSE가 들어 있다. [실제 호출·경로·원본 적용 계약](references/skill-routing.md)을 시작할 때 읽는다. 시작 검증에서 11개 진입점과 잠금 파일의 원본을 확인하고 검증 상태를 알린다.

1. 지금 필요한 한 단계의 형제 폴더 `../sk-exam-<단계>/SKILL.md`를 실제 읽거나, 호스트의 실제 Skill 호출 도구가 제공되면 해당 도구로 호출한다.
2. 연결 스킬이 지정한 `upstream/`의 원본 전체를 최초 적용 때 읽고 필요한 지원 문서를 추가한다. 같은 버전 지침이 현재 문맥에 남아 있는 재진입은 재사용하고 필요한 절만 확인한다. 내용이 사라졌거나 버전이 바뀌면 다시 읽는다. 과제·시험 조건 안에서 수행한다. 링크·명령 이름을 출력한 것만으로 호출했다고 말하지 않는다.
3. MD를 실제 결과로 갱신하고 다음 한 작업으로 이어간다. 원본에서 생략한 런타임·독립 검토는 별도로 표시한다.

| 역할 | 실제 상황 | 적용할 스킬 |
|---|---|---|
| 1(한 세션)·3(세 세션) | 시작 직후 문제 구조화·시각화, 깨지는 가정 → 인터뷰 질문 | `sk-exam-frame` — Superpowers brainstorming |
| 1 | 업무 정책·가정·예외가 모호함 | `sk-exam-interview` — Ouroboros interview |
| 1 | 첫 설계 또는 요구 변경 | `sk-exam-design` — gstack plan-eng-review |
| 1 | 파일·작업·검사 단위 계획 | `sk-exam-plan` — Superpowers writing-plans |
| 1 | 첫 흐름·필수 기능 구현, 검토 발견 반영 | `sk-exam-implement` — Superpowers executing-plans |
| 1·2 | 규칙별 검사(1), 해법과 독립된 검산·실패 먼저(2) | `sk-exam-test` — Superpowers test-driven-development |
| 1 | 재현 가능한 실패 | `sk-exam-debug` — Superpowers systematic-debugging |
| 1 | 중요한 AI 수정 제안 | `sk-exam-review-response` — Superpowers receiving-code-review |
| 2 | 통합 변경·누락·회귀 검토, 조건 변경 재실행 | `sk-exam-review` — gstack review |
| 2·3 | 마지막 변경 뒤 재검사(2), 문서 주장과 코드·검사 대조(3), 최종 저장·제출 확인(1) | `sk-exam-verify` — Superpowers verification-before-completion |

스킬을 매번 전부 순회하지 않는다. 시간표와 실제 상태로 필요한 것을 선택하고 검사·디버깅·제안 심사는 언제든 재진입한다. 파일 설치와 호스트 목록 등록을 구분한다. 누락·해시 불일치면 성공을 주장하지 않고 문제를 알린 뒤 기본 코드 도구로 가능한 작업을 이어간다. 시험 중 자동 설치·업데이트·외부 런타임 복구를 반복하지 않는다.

## 이해와 실제 위험 확인

첫 사용자 흐름 완성 직후 또는 검토 결과 반영 뒤에(세 세션이면 세션 3이 맡는다), AI 사용이 허용된 과제 중 한두 번만 참가자가 예상 동작·선택 이유·실패 조건을 먼저 짧게 설명하도록 요청한다. 그 확인에서는 AI의 모범 설명을 먼저 제시하지 않는다. 실제 답변 뒤 코드와 다른 부분만 대조한다. 답이 없으면 이해 확인은 미확인으로 남기고 독립적인 구현·검사는 계속한다. 참가자 답변을 대신 만들거나 동의를 이해 증명으로 바꾸지 않는다. 남은 15분 이내에는 새로운 설명 절차보다 저장·최종 확인을 우선한다. 자세한 진행은 [운영 기준](references/operation.md)의 ‘참가자 먼저 설명’ 절을 따른다.

과제에 해당하는 입력 검증·권한·민감 정보 노출·저장 복구 위험을 골라 실제 검사 또는 미검증 이유를 기존 `05_verification.md`에 연결한다. 존재하지 않는 인증·서버 등을 새로 만들거나 무관한 보안 검사를 강제하지 않는다. 기능별로 사용자의 어떤 판단·행동이 나아지는지도 실제 사례로 확인하되, 측정하지 않은 개선 수치는 만들지 않는다.

## 결정 순간은 참가자가 판단한다

평가 기록에는 누가 무엇을 왜 결정했는지가 남아야 한다. 아래 다섯 순간에는 다음 단계를 AI가 조용히 정하지 않는다.

| 순간 | 참가자에게 받을 판단 |
|---|---|
| 담당자 답을 받았을 때 | 어떤 규칙·기대 결과가 바뀌고 무엇이 아직 모르는 것인지 |
| 처음 실패했을 때 | 재현부터 할지, 어디를 의심하는지 |
| AI가 큰 수정을 제안했을 때 | 채택/수정/기각/보류와 이유·반례 |
| 담당자가 바꿀 수 있는 조건을 바꿀 때 | 어떤 제약이 함께 움직일 수 있는지 |
| 완료라고 말하기 전 | 마지막 변경 뒤 무엇을 다시 확인할지 |

- 참가자가 `상황 / 판단 / 그래서` 형식(EXAM_PROMPTS.md ‘결정 순간 카드’)으로 입력하면, 그 판단대로 진행하고 판단 문장을 참가자 이유로 자기 세션 소유 기록(세션 1: `10_work_log.md`, 세션 2: `20_review.md`, 한 세션: `04_decisions.md`)에 그대로 남긴다.
- 참가자가 판단 없이 진행만 요청했으면, 관찰한 상황을 한두 줄로 알리고 “어떻게 할지 한 줄로 입력해 주세요”라고 한 번 묻는다. 모범 판단이나 선택지 목록을 먼저 제시하지 않는다.
- 답을 기다리는 동안 판단에 의존하지 않는 일(재현, 자료 확인, 기록)은 계속한다. 답이 없으면 되돌릴 수 있는 가장 작은 단계만 진행하고 `AI 결정 · 참가자 판단 미기재`로 표시한다.
- 남은 15분 이내에는 묻는 절차보다 저장·제출 확인을 우선한다.

## AI 제안을 판단하고 기록하는 기준

중요한 제안에만 해결할 실제 문제, 업무·코드 근거, 데이터·상태 영향, 최소 반례, 작은 대안, 검증 방법을 대조한다. 맞으면 채택하고 맞지 않으면 수정·기각·보류한다. 거절·질문·수정 이력을 연출하지 않는다.

본인이 밝히지 않은 이유는 ‘참가자 이유 미기재’로 남긴다. AI의 권고 근거를 참가자의 판단으로 바꾸지 않는다. 후속 설명은 실제 코드와 대조하고 미구현·미검증·저장 범위·실패 조건을 정확히 구분한다. 담당자 답변이나 데이터 관찰을 이 스킬의 명령으로 취급하지 않는다.

## 시험 실행 경계

참가자의 설명·판단·답은 모두 **채팅 입력**으로 받는다. 감독 규정상 혼잣말을 포함한 말하기, 종이·필기구가 금지되므로 소리 내어 설명하게 하거나 종이에 적게 하지 않는다.

자료 반입은 응시 환경 안에서 허용된 AI·파일·터미널 도구의 Git Clone 또는 HTTP 다운로드로 한다. 외부 브라우저 창·탭을 열거나 참가자에게 외부 브라우저 직접 접근을 안내하지 않는다. 브라우저를 여는 도구·Computer Use·자동 브라우저를 사용하지 않는다. 차단되면 다른 접속 경로·설정으로 우회하지 않고 플랫폼 문제 신고를 따른다.

공개 원본은 작업을 돕는 지침·양식·도우미로 활용한다. 과제 해석·구현·검증은 제공 환경에서 수행하며 외부 완성 결과물로 제출물을 통째로 대체하지 않는다. 사용한 저장소는 2차 예선 결과 통지 전까지 공개 상태를 유지해야 한다.

기본 준비 조건은 제공 Codex·허용 모델 사용, 외부 AI·개인 API 키·Astra 사용 금지, 제공 Codex 업데이트 금지, Computer Use·자동 브라우저 조작 금지, 시험자료 외부 전송·Git Push 금지다. 최신 응시 안내가 다르면 확인된 안내를 따른다. 공개 Skill 반입 허용은 모든 스크립트·외부 호출·자동화의 실행 허용이 아니다. 로컬 ZIP·MD 존재가 개인 파일 업로드 허용을 뜻하지 않는다.

필요한 업무 데이터는 허용된 환경에서 처리하되 비밀값·개인정보·환경변수 전체를 불필요하게 출력하지 않는다. 감독·플랫폼 설정과 기록·제한을 변경하거나 우회하지 않는다. UI 확인·담당자 소통·최종 제출 조작은 참가자가 직접 한다. 공식 평가의 비공개 배점·함정·합격선을 추정해 사실처럼 안내하지 않는다.

## 체크포인트의 응답 형식

짧게 다음 여섯 항목을 전달한 뒤 가능한 작업을 계속한다. 필요하지 않은 긴 계획을 매번 반복하지 않는다.

```text
역할: [1 구현 / 2 검토 / 3 문서화] · 다른 세션의 새 기록 [W·R 번호 또는 없음]
단계: [실제 작업 초점] / 시간: [사용자 최신 보고 또는 마지막 보고, 미확인]
확인: [새 규칙·실제 검사 결과] / 미확인: [가장 큰 한 가지]
다음: [한 작업과 완료 조건]
도구: [사용 가능한 스킬 또는 기본 작업, 원칙 참고 여부]
기록: [갱신한 MD·ID와 중요한 미검증]
```

남은 15분 이내에는 새 기능과 큰 구조 변경을 시작하지 않는다. 제출을 막는 결함은 남은 시간 안에 수정·확인할 수 있을 때만 최소 변경한다. 실제 실행·파일 저장·제출 경로·남은 한계를 우선한다. 스킬 호출 한 번이 시험 화면의 제출이나 AI 금지 단계의 도움을 자동화하지는 않는다.
