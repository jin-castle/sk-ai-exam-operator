# 실행 근거 가드

`scripts/evidence_guard.py`는 Python 표준 라이브러리만 사용하는 선택적 도구다. 스킬 유지보수 및 AI 사용이 허용된 과제 작업 중 실제 검사 명령을 기록한다. 단계·시험 규칙·실제 잔여 시간은 기존 운영 지침을 따른다. 금지 단계에는 상태 조회를 포함한 도구 호출을 하지 않는다.

## 무엇을 확인하는가

- 등록한 필수 항목마다 최신 성공 검사 근거가 있는지 확인한다. 요구사항 내용·기대 동작·출처가 달라지면 기존 검사를 다시 수행한다.
- 지정한 파일/폴더의 경로·바이트·파일 크기·수정 시각·파일 식별자·모드를 실행 전후·현재 시점에 비교한다. 이 비교에서 드러난 실행 중 변경, 이후 수정·추가·삭제는 이전 검사의 근거를 무효화한다. 내용이 같아도 일반적인 임시 수정 후 복원이나 파일 교체는 재검사를 요구한다.
- 명령은 프로젝트 폴더에서 shell 없이 실제 실행하고 출력·종료 코드를 기록한다. 최신 실패·실행 불가·시간 초과가 과거 성공으로 가려지지 않게 한다.
- 로그가 사라지거나 변경되면 근거로 사용하지 않는다. 상태 조회는 파일을 만들거나 갱신하지 않는다.

가드는 필수 항목의 등록 누락, 틀린 기대값, 부실한 테스트, 데이터 누수, 무의미한 `exit 0`을 자동 판별하지 않는다. 명령이 성공해도 테스트 수·assertion·기대 출력과 실제 업무 사례를 확인한다. 빌드·단위 검사·업무 규칙·수동 UI 관찰의 근거를 구분한다. `recorded_checks_current`는 전체 과제 완료나 공식 제출 가능 판정이 아니다.

## 사용 예

아래 `GUARD`는 실제 설치된 `sk-ai-exam-operator/scripts/evidence_guard.py`, `PROJECT`는 현재 과제의 절대 경로로 바꾼다. 필요한 Python이 이미 있을 때만 실행하며 추가 설치는 하지 않는다. `--project`는 하위 명령보다 먼저 전달한다.

```text
python -X utf8 -B GUARD --project PROJECT require --id F1 --text "빈 CSV를 거부한다" --acceptance "헤더만 있는 CSV에 명확한 오류를 반환한다" --source "과제 README의 입력 조건"
python -X utf8 -B GUARD --project PROJECT check --id T1 --for F1 --watch src --watch tests --watch pyproject.toml --timeout 120 -- python -B -m unittest discover -s tests
python -X utf8 -B GUARD --project PROJECT status
```

프로젝트에 없는 경로를 예시 그대로 쓰지 않는다. `--watch`에는 현재 검사와 관련된 소스·설정·입력 데이터·테스트를 실제 프로젝트 기준 상대 경로로 모두 지정한다. 입력 파일이나 설정을 빼면 그 변경은 감지되지 않는다. 요구사항/예외는 기존 F/E ID와 연결하고, 실제 과제에 필요한 항목을 확인해 등록한다. 수동 관찰은 자동 명령으로 꾸미지 않고 본문 MD에 참가자 보고로 남긴다.

`--watch`는 여러 번 지정할 수 있다. 전체 프로젝트를 지정할 때는 `.git`, `node_modules`, `.venv`, `venv`, `__pycache__`, `.pytest_cache`, `.mypy_cache`, `.ruff_cache`, `.next`, `dist`, `build`, `coverage` 및 가드 자체 저장소가 재귀 탐색에서 제외된다. 제외 폴더 안의 파일도 직접 `--watch`로 지정하면 검사 대상이 된다. 빌드 결과물 자체가 필수 산출물이면 그 실제 파일을 직접 지정한 별도 검사를 사용한다. 명령이 쓰는 임시 출력은 소스/입력 범위와 분리한다.

검사 로그는 실제 출력 원문이므로 민감 정보를 출력하는 명령은 사용하지 않는다. 명령 인수에도 비밀값을 넣지 않는다. 가드는 외부 전송·자동 제출·상시 감시·전역 설정 변경을 하지 않는다. 다른 명령의 실행 권한을 확장하는 보안 샌드박스도 아니다.

## 결과를 읽는 법

- `status`의 종료 코드 0: 등록한 필수 항목에 현재 파일과 일치하는 성공 검사 기록이 있다. 실제 JSON의 검사 범위와 로그를 함께 읽는다.
- 종료 코드 2: 필수 항목/검사 누락, 실패, 오래된 근거, 잠금, 잘못된 경로/상태 등 원인을 확인한다. 완료라고 쓰지 않고 해당 검사를 수정·재실행한다.
- `check`의 비영 종료: 명령 실패·실행 불가·시간 초과 또는 근거 수집 문제다. 실제 JSON의 결과·종료 코드와 로그를 확인한다. 예상 출력을 실제 출력으로 대신 쓰지 않는다.

같은 검사 ID를 재실행하면 최신 결과가 판정 기준이다. 다른 ID의 실패도 남아 있으면 숨기지 말고 그 검사에서 드러난 결함을 해결·재검증한다. 요구사항이 바뀌었으면 `require`로 같은 ID를 갱신하고 필요한 검사를 다시 실행한다. 근거를 통과시키려고 상태 JSON이나 로그를 수동 편집하지 않는다.

유효한 검사 ID로 실행을 요청했지만 경로·옵션 등의 문제로 거부된 경우도 `rejected_attempt`로 남는다. 같은 ID의 실제 검사를 올바른 범위에서 성공시키기 전에는 과거 성공을 완료 근거로 선택하지 않는다. 잘못된 CLI 형식으로 인한 인자 파싱 오류는 실행 기록을 만들지 않으므로 호출 자체가 성공했는지도 먼저 확인한다.

동시 수정/검사에는 저장소 잠금을 사용한다. 검사 중이거나 잠금 파일이 남아 있으면 상태를 통과로 표시하지 않는다. 비정상 종료 뒤 잠금이 남았다면 해당 가드·명령 프로세스가 종료됐는지 먼저 확인하고 기존 기록을 보존한 뒤 잠금을 복구한다. 실행 중인 다른 검사의 잠금을 자동 삭제하지 않는다. 서로 다른 가드 저장소의 동시 실행까지 조정하지는 않는다.

## 기록과 한계

기본 저장소는 프로젝트 안의 `exam-notes/.evidence-guard/`다. 동등한 기존 기록 위치를 쓸 때는 `--store`에 프로젝트 안의 충돌 없는 상대 경로를 하위 명령 앞에서 지정한다. 이 도구는 기존 `.operator-state.json`, `00_status.md`, 다섯 본문 MD를 관리하지 않는다. 프로젝트 밖 경로와 링크 경로를 거부한다. 상태 JSON은 로컬 사용자 편집까지 방어하는 위변조 방지 장치가 아니다.

이 도구는 파일 시스템의 변경 이력을 연속 감시하지 않는다. 실행 중 변경 후 내용과 모든 비교 메타데이터가 원상 복구된 경우는 놓칠 수 있다. fingerprint 버전이 다른 과거 기록은 원문을 보존하고 `snapshot_algorithm_changed`로 표시하므로 현재 버전으로 검사를 다시 실행한다.

관련 환경 변수·외부 서비스·미지정 파일·패키지 환경이 바뀐 경우 파일 지문이 같아도 새 검사가 필요하다. Python이 없거나 스크립트가 허용되지 않으면 실제 명령·출력·검사 시점과 변경 파일을 기본 도구로 비교하고 자동 최신성 검사를 수행하지 못했다고 밝힌다.
