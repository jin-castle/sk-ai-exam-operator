# MD 기록 계약과 재개

기본 기록 폴더는 현재 과제의 `exam-notes/`다. 지정 기록 위치나 동등한 파일이 있으면 재사용하고 아래 역할을 그 위치에 매핑한다. 기존 원문·README·상태 파일을 덮어쓰지 않는다.

## 다섯 역할

| 파일 | 기록 내용 |
|---|---|
| `01_domain.md` | Q: 실제 답변·자료 위치, 업무 규칙·용어, 근거 상태, 미해결·충돌 |
| `02_requirements.md` | F: 사용자 행동, 필요한 데이터·규칙·의존성, 성공 기준, 범위·진행 상태 |
| `03_exceptions.md` | E: 조건·반례, 기대 처리, 정책 근거, 실제 구현 위치·검증 연결 |
| `04_decisions.md` | D: 실제 AI 제안, 참가자 실제 선택과 이유, 영향·검증, 재검토 조건 |
| `05_verification.md` | T: 기대·실제, 명령·직접 관찰·근거, 통과·실패·미검증, 실제 시스템 흐름과 한계 |

Q→F→E→D→T는 추적을 돕는 방식이다. 모든 행에 모든 ID를 강제하지 않는다. ID를 재사용해 다른 사실로 바꾸지 말고 기존 내용을 수정하면 이유와 새 근거를 남긴다.

근거 상태는 **과제 명시 / 담당자 확인 / 데이터 관찰 / 참가자 가정 / AI 제안 / 미확인**이다. 사용자의 메시지에 담당자 답변이 인용돼 있다면 ‘참가자가 전달한 담당자 답변’으로 출처를 적는다. AI 추론으로 답변을 보충하지 않는다. 확인된 정책이 바뀌면 연결된 기능·예외·검사를 점검한다.

검증은 **통과 / 실패 / 미검증**이다. 계획된 검사는 기본 미검증이고 예상 출력을 실제 출력으로 쓰지 않는다. 빌드·규칙·수동 UI·저장 실패 주장을 구분한다. 참가자가 직접 봤다고 전달한 결과는 ‘참가자 보고’로 적는다. AI가 직접 실행한 검사는 실제 명령·출력·시점을 근거로 적는다.

중요한 판단 이유는 참가자가 실제 말한 내용만 쓴다. 없으면 ‘참가자 이유 미기재’라고 한다. AI가 제안한 이유는 AI 제안으로 표시한다. 참가자가 실제로 선택한 사실과 이유를 구분한다.

## 상태와 시간

선택적 스크립트는 `.operator-state.json`과 생성된 `00_status.md`만 소유한다. 다섯 본문 MD는 초기 파일이 없을 때만 생성하고 이후에는 수정하지 않는다. Codex가 실제 대화·코드·검증에 따라 본문을 관리한다.

스크립트가 다섯 파일을 만든 것은 그 내용의 사실 확인이나 업무 진행을 의미하지 않는다. `00_status.md`의 시간 구간은 마지막 보고를 이용한 권고이며 실제 현재 단계는 Codex가 근거로 결정한다.

재개할 때는 상태·최근 기록·현재 코드 상태를 읽는다. 타이머를 180으로 재설정하거나 이미 확인한 인터뷰를 반복하지 않는다. 구조가 다르거나 손상된 상태 파일은 덮어쓰지 않고 원본을 보존한다. 대체 기록 위치가 필요하면 과제 안의 충돌 없는 새 위치를 선택하고 사용자에게 짧게 알린다.

## 짧은 체크포인트

실제 기능·대화 묶음 끝에 바뀐 사실만 갱신한다. 별도 대화 전체 복사본과 중복 요약은 만들지 않는다. 문서 작성은 실제 문제 해결·검증을 돕는 범위로 제한한다.

선택적 상태 파일은 잔여 시간, 보고 시점, 시간별 권고만 저장한다. 개인정보·원문 프롬프트·담당자 전체 대화를 넣지 않는다. 보고 시점은 감사용 메타데이터이며 잔여 시간을 계산하는 데 쓰지 않는다.


## 원본 스킬 적용 기록

`05_verification.md`에 사용한 연결 스킬·실제로 읽은 원본/지원 파일·적용 절차·중요 생략·실행 근거를 짧게 연결한다. 전체 형식은 [skill-routing.md](skill-routing.md)를 따른다. 원본 읽기, 호스트 스킬 등록, 코드 검사 통과는 각각 다른 사실이다.
