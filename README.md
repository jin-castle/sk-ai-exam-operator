# SK AI Exam Operator — v3.0.2 원본 포함 스킬 팩

SK AI 해커톤·Probe의 180분 과제를 **세 세션(1 구현 · 2 검토 · 3 구조화·문서화)**으로 나눠 운영하는 개인 팩입니다. 담당자 답변을 업무 규칙·기능·예외·판단·검증 MD로 연결하고, 남은 시간과 실제 상태에 따라 인터뷰·계획·구현·테스트·검토·검증 스킬을 이어갑니다. 대회나 원본 프로젝트의 공식 시험 스킬은 아닙니다.

**[시험 시작 때 한 번 입력할 설치·시작 프롬프트](EXAM_PROMPTS.md)**를 사용하세요. 고정 ref는 `v3.0.2`입니다(`v3.0.1`: 세션 간 파일 소유권·경로 모순 수정, `v3.0.2`: 설명은 모두 채팅 입력으로·규정 대조표 추가). 기존 버전 태그(2차 예선에 사용한 `v2.2.0` 포함)는 이동하지 않습니다.

## v3.0.0 세 세션 운영

세션 1이 만들고, 세션 2가 세션 1의 결과를 검토하고, 세션 3이 1·2의 작업을 구조화해 문서로 만듭니다. 같은 작업 폴더를 공유하고, 각 세션은 자기 파일만 씁니다. 연락은 파일과 참가자를 통해서만 합니다.

| 세션 | 하는 일 | 쓰는 파일 | 하지 않는 것 |
|---|---|---|---|
| 1 구현 | 인터뷰·설계 → 가장 단순한 end-to-end → 필수 기능, 검토 발견 반영 | 과제 코드·결과물, `10_work_log.md` | 검토·문서 파일 수정 |
| 2 검토 | 구현 전 기대값 → 독립 검사기(망가뜨린 입력으로 FAIL 먼저) → AI가 혼자 정한 것·요구 충족·품질 → 조건 변경 재실행 | `20_review.md`, `exam-notes/review/` | 과제 코드 수정(발견만), 커밋 |
| 3 구조화·문서화 | 작업 로그·검토 기록을 Q/F/E/D/T와 `06_handoff.md`·제출 문서로 구조화, 근거 대조, 기록에 없는 이유는 참가자에게 질문 | `00_problem_map.md`, `01~06`, 제출 문서 | 코드·판정 변경, 이유 대필, 커밋 |

- **문제 구조화(`sk-exam-frame`)**: **참가자가 먼저, AI는 빈칸만** 순서로 진행합니다. AI가 자료 사실을 정리하면 참가자가 문제·원인·위험한 가정·질문 3개를 자기 말로 먼저 쓰고, AI는 빠진 범주만 짚고, 참가자가 고르고 고쳐 씁니다. 가정·질문마다 출처(참가자 / AI 제안)가 남아 평가 기록에 참가자의 이해가 먼저 보이게 합니다. 시작 직후 과제를 한 장의 문제 지도(풀어야 할 문제·근본 원인 가설·시스템 경계·접근 순서)와 그림으로 정리합니다. 그림은 이미지 생성 도구 대신 `skills/sk-exam-frame/scripts/frame_viz.py`(표준 라이브러리, matplotlib·한글 글꼴이 있으면 PNG도)로 그립니다. 문제 지도(원인→문제→증상, 입력→처리→출력→사용자, 가정→깨지는 지점→질문)와 데이터 산점도(결측·범위 밖 이상값 개수 요약)를 만듭니다. 핵심은 30분 바이브 코딩 해법이 깔고 있는 가정을 뽑아 “현실이 다르면 어디서 틀리나”로 바꾸고, 그것을 영향 큰 순의 담당자 인터뷰 질문으로 만드는 것입니다. 세 세션이면 세션 3이 시작 직후 맡습니다.
- **결정 순간 카드**: 담당자 답, 첫 실패, AI의 큰 수정 제안, 조건 변경, 완료 주장 직전의 다섯 순간에는 참가자가 `상황 / 판단 / 그래서` 형식으로 판단을 남깁니다. 운영 스킬은 이 순간에 다음 단계를 조용히 정하지 않고 참가자 판단을 먼저 받습니다. 스킬 이름을 많이 부르는 것보다 이 판단 기록이 평가에 남는 핵심입니다([카드](EXAM_PROMPTS.md#결정-순간-카드)).
- [세션별 시작 프롬프트](EXAM_PROMPTS.md): 세션 1이 설치하고, 세션 2·3은 설치 없이 같은 폴더에서 시작합니다.
- 커밋은 세션 1만 합니다. 남은 30분이면 세션 1은 새 기능을 멈추고, 세션 2는 마지막 재검사, 세션 3은 최종 정리에 들어갑니다.
- 세션을 하나만 열 수 있으면 한 세션이 같은 역할을 시간 순서(구현 0~100 → 검토 100~150 → 문서화 150~180)로 맡습니다.
- 세 세션은 같은 파일을 여러 번 읽어 토큰을 더 씁니다. 바뀐 부분만 다시 읽도록 했지만 토큰 사용량이 평가에 쓰인다는 안내가 있으면 감안하세요.
- `exam_session.py init`(세션 1만 실행)이 01~06·10·20 빈 양식을 없을 때만 만듭니다. 내용은 각 소유 세션이 씁니다.
- 연결 스킬이 01~05에 쓰라고 해도 세 세션이면 세션 1은 `10_work_log.md`, 세션 2는 `20_review.md`에 남깁니다. 세션 2·3이 다시 실행하는 명령의 출력은 `exam-notes/review/`로 보내 세션 1의 결과물을 덮어쓰지 않습니다.
- 검토·문서화 장치는 아래 공개 저장소들의 아이디어를 참고해 이 팩의 형식으로 다시 썼습니다(문구·코드는 가져오지 않음): [hongkevin/cofathon-prep](https://github.com/hongkevin/cofathon-prep)(AI가 혼자 정한 것 묻기, 테스트 수정 전 보고), [hamjoon2003/sk-hynix-2nd-harness](https://github.com/hamjoon2003/sk-hynix-2nd-harness)(검사 0건 ≠ 통과), [ripplelover/cofa-ready-kit](https://github.com/ripplelover/cofa-ready-kit)(개선 중단 시각, 기대값 먼저), [zittenyetten/cofa-probe-kit](https://github.com/zittenyetten/cofa-probe-kit)(요구 충족→품질 순서, 수행자 구분), [gxonu/sk-probe-kit](https://github.com/gxonu/sk-probe-kit)(발견 사항 형식, 정정은 새 행), [imhyunho99/cofathon-ai](https://github.com/imhyunho99/cofathon-ai)(작업 기록 색인).

## v2.2.0 실행 근거 검사

- 선택적 `evidence_guard.py`가 등록한 필수 항목과 실제 검사 명령을 연결합니다.
- 관련 소스·설정·입력·테스트의 내용과 파일 메타데이터를 실행 전후·현재 시점에 비교합니다. 일반적인 임시 수정 후 복원도 재검사를 요구합니다.
- 최신 실패·시간 초과·실행 불가·거부된 검사, 누락되거나 변경된 로그를 과거 성공으로 가리지 않습니다.
- 상태 조회는 읽기 전용이며, 기존 본문 MD·타이머를 수정하지 않습니다. Python 표준 라이브러리만 사용합니다.
- [사용법과 감지 범위](skills/sk-ai-exam-operator/references/evidence-guard.md)를 확인하세요. 등록한 항목·지정한 파일 범위의 실행 기록 검사이며, 업무 정답·테스트 충분성·수동 UI 확인을 자동 판정하지 않습니다.

고정 커밋의 **124개 원본 파일을 바이트 그대로 보존**했습니다. 이 수는 원본 스킬 지침 18개와 지원 파일 106개의 합계이며, 설치 진입점은 위의 11개입니다. 원본 `SKILL.md`의 파일명만 `SKILL.original.md`로 저장해 호스트가 지원되지 않는 원본을 별도 스킬로 자동 등록하는 것을 막습니다. [잠금 파일](skills/sk-ai-exam-operator/bundle-lock.json)에 원래 경로·저장 경로·SHA256, [원본 고지](THIRD_PARTY_NOTICES.md)에 출처와 LICENSE가 있습니다. 원본은 운영 스킬 하위 `upstream/`에 함께 설치되고, 10개 연결 스킬은 그 파일을 사용합니다.

원본의 전체 실행 환경까지 설치하지는 않습니다. gstack의 바이너리·Bun·브라우저·telemetry·외부 모델, Ouroboros의 MCP·uvx, Superpowers의 자동 작업공간 전환·merge/push 등은 실행하지 않습니다. 연결 스킬이 원본 절차 중 실제 적용한 부분과 중요 생략을 기록합니다. [호출 계약](skills/sk-ai-exam-operator/references/skill-routing.md)을 참고하세요.

## 설치와 확인

기본 `skill-installer`에서 [설치 프롬프트](EXAM_PROMPTS.md)에 나열한 **11개 경로를 함께 설치**해야 합니다. 운영 스킬 하나만 설치하면 원본은 포함되지만 10개 연결 진입점은 누락됩니다. 기존 대상이 있으면 덮어쓰지 않고 충돌 없는 별도 `--dest`에 팩 전체를 설치해 파일로 적용할 수 있습니다. 목록 등록을 위해 제공 Codex를 업데이트하지 않습니다.

기존 Python으로 체크아웃 검증:

```text
python -X utf8 -B scripts/check_bundle.py --root .
python -X utf8 -B -m unittest discover -s tests -v
```

설치 후 검증:

```text
python -X utf8 -B ACTUAL_OPERATOR_DIR/scripts/check_bundle.py --installed-root ACTUAL_SKILLS_PARENT
```

검증기는 11개 진입점·원본 고정 커밋·124개 SHA256·LICENSE·경로·연결을 읽기 전용으로 확인합니다. 이 결과는 원본 전체 런타임 동작이나 실제 시험 PC 호환성의 증명이 아닙니다. Python이 없으면 파일 확인으로 진행하고 해시 검증 불가를 밝힙니다. 새 런타임이 필요하지 않습니다.

## 기록과 시간 운영

현재 과제의 `exam-notes/` 또는 기존 지정 양식을 사용합니다.

| 기본 문서 | 내용 |
|---|---|
| `01_domain.md` | 담당자 답변·규칙·근거·미확인 |
| `02_requirements.md` | 기능·필요 조건·수용 기준·짧은 실행 계획 |
| `03_exceptions.md` | 예외·기대 처리·코드·검사 연결 |
| `04_decisions.md` | 실제 AI 제안·참가자의 실제 선택과 이유 |
| `05_verification.md` | 실제 검사·시스템 흐름·한계·스킬 적용 기록 |
| `06_handoff.md` | 세션 3이 구조화한 인계 문서: 구현·검토·AI 제안과 검토·감수한 한계·최종 상태 |
| `10_work_log.md` | 세션 1의 작업 로그: 담당자 답변 원문, 작업 묶음별 실행 결과·AI가 스스로 정한 것 |
| `20_review.md` | 세션 2의 검토 기록: 구현 전 기대값, 독립 검사기, 발견, 조건 변경 재실행 |

잔여 시간은 참가자가 실제 화면에서 확인해 전달한 값만 사용합니다. 자동 타이머·알람·브라우저·제출 자동화는 없습니다. 이미 확인한 정책·기존 구현·검사 기록을 재사용합니다. 선택적 `exam_session.py`는 시간 보고와 빈 양식을 관리하며 본문을 덮어쓰지 않습니다.

## 사용 경계

최신 응시 안내와 제공 환경의 허용 범위가 우선합니다. 실제 과제 데이터·답변·로그를 이 공개 저장소로 Push하지 않습니다. 참가자가 밝히지 않은 판단 이유나 실행하지 않은 테스트 결과를 만들지 않습니다. AI 금지 후속 서술형에 들어갔다는 보고가 오면 문항 분석·답안·첨삭·파일 작업을 멈춥니다.

| 외부 브라우저 직접 접근 불가, 필요한 정보는 플랫폼 안 AI로 | 브라우저를 열지 않음. 원본의 Visual Companion 서버는 실행하지 않음 |
| 문제·파일·결과물 외부 전송·게시 금지, Git Push 불가 | 로컬 커밋만(세션 1). Push·업로드·원격 요청 없음 |
| 외부 코드는 참고·일부 알고리즘 차용까지, 결과물 통째 대체 불가 | 과제 풀이 코드·데이터를 포함하지 않음. 운영 지침·기록 양식·검사·시각화 도구만 |
| Computer Use·자동 조작 금지, 감독·차단 우회 금지 | 금지 명시. UI 확인·담당자 대화·제출은 참가자가 직접 |
| 과제 제출 문서는 코딩 에이전트와 함께 작성 가능, 서술형은 AI·복사/붙여넣기 없이 | 문서화 세션은 과제 시간 안의 기록 정리만. AI 금지 단계 보고 시 모든 지원 중단 |
| 혼잣말 포함 말하기·종이·필기구 금지 | 참가자 설명·판단은 모두 채팅 입력으로 받음 |
| 기록(대화·터미널·Git·테스트)·토큰 사용량 수집 | 실행하지 않은 검사·판단을 만들지 않음. 세 세션은 토큰을 더 쓰므로 바뀐 부분만 다시 읽음 |

확인이 필요한 회색 영역: 제공 환경에서 Codex 세션을 여러 개 동시에 여는 것이 허용·지원되는지(안내 요약에 금지 문구는 없음), 스킬을 Codex 기본 스킬 폴더에 설치하는 것이 ‘제공 환경의 적용 방법’에 맞는지(막히면 `--dest`로 도구 폴더에 받아 파일로 적용).

## 도구·자료 안내에 맞춘 반입

개인 사전 제작 지침·Skill·템플릿·코드의 공개 후 반입 허용 안내에 맞춰 구성했습니다. 응시 환경 안에서 AI를 통해 Git Clone/HTTP 다운로드로 받으며 외부 브라우저 직접 접근·개인 PC 파일 업로드·시험자료 외부 전송·Git Push·차단 우회를 하지 않습니다. 질문 초안은 참가자가 직접 검토한 뒤 사용하고, 외부 완성 결과물로 제출물을 통째로 대체하지 않습니다. 사용한 저장소는 2차 예선 결과 통지 전까지 공개 상태를 유지해야 합니다. 이 설명은 제공된 안내와의 대조이며 주최사의 별도 승인·평가 결과를 보장하지 않습니다.
